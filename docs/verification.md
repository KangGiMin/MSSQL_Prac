# 수정과 검증

이 문서는 일곱 우선순위의 수정 위치와 실제 검증 방법을 설명합니다.

| 범위                | 수정 내용                                                                                    | 검증                                                 |
| ------------------- | -------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| DB 준비·연결        | 비파괴 준비, DB별 health, 재연결 시 스키마 갱신, 프로세스 간 잠금                            | SQL 통합, HTTP, 연결 장애 브라우저 검사              |
| 실행 단축키         | 우선순위 키맵, 공통 실행 조건, 선택 영역, 취소 후 정리 대기                                  | Ctrl+Enter·F5·선택 영역·연결 실패·취소 브라우저 검사 |
| 저장·탭 충돌        | 저장값 검증, 실패 상태, 안전한 재시도, Web Locks/IndexedDB 잠금, 탭별 복구 SQL               | 잘못된 값·저장 공간 부족·두 탭·재시도 브라우저 검사  |
| 작성 내용 보호      | 교체 전 보관, 보관 실패 시 교체 중단, 복원·목록 정리, 백업 가져오기/내보내기                 | 교체·복구·잘못된 백업·새 컨텍스트 복원 검사          |
| 오류·화면           | HTTP 400/409/503 분류, 읽을 수 있는 DB 오류, 반응형 버튼, 메뉴 포커스·Escape, 오류 복구 화면 | API·모바일·대체 화면 브라우저 검사                   |
| 회귀 검사           | 결과값·행 수 검증, 연속 DDL·CASCADE, 취소·시간 제한, 다중 프로세스 잠금                      | SQL 통합 및 순차 verify                              |
| 스키마·CSV·설정·PDF | 정확한 타입·다중 FK, NULL 구분·헤더 보호·JSON, 포트 연동, 실제 PDF 페이지 수·교체 복구       | SQL 회귀, 단위, 포트, PDF·내보내기 브라우저 검사     |

## 검증 경계

- SQL 통합 검사는 학습 답안 71개의 실행 성공 외에 주요 행 수·값·정렬·NULL 평균·JOIN·CASCADE와 연속 실습을 확인합니다. 교육적 의미 전체를 자동 채점하는 도구는 아닙니다.
- 실제 SQL 회귀는 긴 JSON/바이너리, 결과 용량 제한, 여러 FK, 타입 의존성, 시간 테이블·DB 트리거·스키마 초기화를 검사합니다.
- PDF 검사는 별도 임시 디렉터리에서 실제 파일을 가져오고 실패 시 원본 유지와 메타데이터 일치를 검사합니다.
- 브라우저 저장 실패와 손상 검사는 테스트 전용 컨텍스트에서 수행합니다.
- 전체 검증은 SQL 초기화 검사를 병렬 실행하지 않습니다. 개별 검사를 별도 터미널에서 동시에 실행하면 DB 잠금에 의해 충돌이 거부될 수 있습니다.
- Windows 통합 인증과 설치된 Chrome 환경을 기준으로 검증합니다. 다른 SQL 인증 환경에는 실제 자격 증명·서버 설정에 맞춘 추가 접속 검증이 필요합니다.

## 운영 확인

`npm.cmd run verify`가 소스·실제 DB·빌드·렌더링·HTTP·브라우저 검사를 순서대로 실행합니다. `npm.cmd run format:check`는 별도로 실행하거나 CI에서 확인합니다. API 및 프런트 주소를 변경한 경우 `npm.cmd run test:ports`로 프록시와 포트 충돌 동작을 확인합니다.

저장 공간 부족 시 기존 데이터를 자동 삭제하지 않습니다. 전체 백업을 내려받고 필요 없는 보관 항목을 정리한 뒤 다시 저장합니다. 전체 백업에는 정상화한 현재 상태와 복구를 위한 원본 저장 자료가 포함됩니다.

## 검증 실행 결과

Windows / Node.js 24 / SQL Server 17 / Chrome 환경에서 단위 11개, SQL 통합 83개(학습 답안 71개 포함), SQL 회귀 5개, 포트 2개, HTTP 17개, 브라우저 23개를 통과했습니다. 빌드·React 렌더링·포맷 검사도 통과했습니다.
